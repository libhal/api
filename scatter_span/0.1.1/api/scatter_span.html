scatter_span<T>#

Defined in namespace mem

import scatter_span;

template<typename T>
class scatter_span#

Non-owning immutable view over a collection of disjoint memory spans.

Works similarly to std::span, but the viewed elements do not need to be contiguous in memory. Each constituent chunk is a separate std::span<T const>. Iterating yields each chunk a span in order.

Prefer scatter_span for ad-hoc, call-site construction. Commonly used for when forwarding discontiguous buffers to an API without a heap allocation or memcpy. Prefer scatter_array when the span set is reused or must outlive the call site.

Example
void send_packet(mem::scatter_span<std::byte> payload);

static std::array<std::byte, 4 const> header = { ... };
std::array<std::byte, 8> body   = { ... };
std::array<std::byte, 2> crc    = { ... };

// Three discontiguous buffers assembled into one logical packet inline,
// with no heap allocation or memcpy:
send_packet({ header, body, crc });

Template Parameters:

T – Element type. Elements are always accessed as T const.

Subclassed by mem::scatter_array< T, N >

constexpr scatter_span_iterator<T> begin() const && = delete#

Deleted overload preventing iteration over a temporary scatter_array.

scatter_array owns its span-array storage (m_internal_arr). Calling begin() on an rvalue would produce an iterator that outlives the scatter_array temporary destroying that storage, leaving the returned iterator dangling into freed memory. This overload is deleted to force a compile-time error at the call site instead of runtime undefined behavior.

Example (rejected at compile time)
// ERROR: use of deleted function
auto it = mem::scatter_array(a, b, c).begin();
Fix: bind to a named variable first
auto ssa = mem::scatter_array(a, b, c);
auto it = ssa.begin();  // OK — ssa outlives `it`

constexpr scatter_span_iterator<T> end() const && = delete#

Deleted overload preventing end-iteration over a temporary scatter_array.

Mirrors begin() const&& = delete for the same reason: an end-iterator produced from an rvalue scatter_array would reference storage (m_internal_arr) that no longer exists once the temporary is destroyed at the end of the full-expression.

Example (rejected at compile time)
// ERROR: use of deleted function
auto it = mem::scatter_array(a, b, c).end();
Fix: bind to a named variable first
auto ssa = mem::scatter_array(a, b, c);
auto it = ssa.end();  // OK — ssa outlives `it`

inline constexpr scatter_span<T> sub_scatter_span(sub_scatter_span_args p_args) &#

Returns a sub-view of this scatter_span starting at a logical element offset.

Analogous to std::span::subspan. No data is copied; the returned scatter_span references the same underlying memory with adjusted trim values. If p_args.offset is at or beyond the total length, an empty scatter_span is returned. If p_args.count exceeds the remaining elements it is clamped to the available length.

Example
std::array<int, 3> a = { 1, 2, 3 };
std::array<int, 2> b = { 4, 5 };
std::array<int, 4> c = { 6, 7, 8, 9 };
mem::scatter_array<int, 3> ssa(a, b, c);  // length 9

// Logical elements [2, 7) → { 3, 4, 5, 6, 7 }
auto sub = ssa.sub_scatter_span({ .offset = 2, .count = 5 });

Parameters:

p_args – Offset and count describing the desired sub-range.

Returns:

A new scatter_span<T> covering the requested elements.

constexpr scatter_span<T> sub_scatter_span(sub_scatter_span_args p_args) && = delete#

Deleted overload preventing sub-view creation from a temporary scatter_array.

sub_scatter_span() returns a scatter_span<T> that views scatter_array's internally owned span array. If called on an rvalue, the returned scatter_span would reference storage destroyed at the end of the full-expression that created the temporary scatter_array, leaving the result dangling. This overload is deleted so misuse fails to compile rather than producing a sub-view that reads freed memory.

Example (rejected at compile time)
// ERROR: use of deleted function
auto sub = mem::scatter_array(a, b, c).sub_scatter_span({ .count = 5 });
Fix: bind to a named variable first
auto ssa = mem::scatter_array(a, b, c);
auto sub = ssa.sub_scatter_span({ .count = 5 });  // OK — ssa outlives sub

Note

This restriction applies only to scatter_array, which owns its span storage. scatter_span itself is safe to construct and use as a temporary, since the data it views lives in the caller’s expression, not in the scatter_span object.

scatter_span_iterator<T>#

template<typename T>
class scatter_span_iterator#

Forward iterator over the constituent spans of a scatter_span.

Each dereference yields a std::span<T const> representing one contiguous segment.

The current pointer element is cached allowing for reads via the operator* and operator-> to be constant time.
